# Bounded inspection bundles retain uncertainty and source reuse

On one pinned development example, native one-hop retrieval exposes one registry-positive pair; bounded bank expansion exposes two positives and two unknown pairs, adding 1,140 source-token proxies. There are zero real prior judge-confirmed seeds in the prototype execution; source-gold/oracle seeds remain visibly distinct. No agent productivity or new-family gain was measured.

A refactoring agent may inspect nearby operations cheaply after reading a useful pair. A transport must preserve evidence boundaries so navigation does not silently become a duplicate finding.

## What was tested

Schema-2 bundles reuse native Candidate/Function/Finding/Report models and bind revision, scope, source and background digests. Render each exact function once and limit extra reading to a 6,000-source-token proxy; an oversized anchor requires explicit escalation rather than truncation. Relationship edges are navigation, not transitive duplicate proof. Leads cannot become reported, related or blocking without the appropriate authority.

A wrapper can call the same shared implementation as its neighbor. Its graph edge is useful navigation but is not independent duplicated ownership; bundle state must retain already-shared, rejected, disputed and unknown outcomes.

## Decision and limits

Retain bounded optional inspection and strict authority separation. Do not promote graph-connected code to reports. Later adaptive source reviews are preserved separately in private corpus evidence.

This is recovery of an existing frozen experiment. No providers, new encoder inference, new mining or new experiments ran during packaging. Source-positive labels, provider answers, retrieval ranks and emitted reports retain their separate meanings. The original report and earlier failures remain in the private archive; this recovery report corrects interpretation without overwriting them.
