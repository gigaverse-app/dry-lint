Acceptance contract: byte-exact ordered region tokens; float.hex-exact vectors and returned scores; unchanged candidate ordering/native identities; unchanged eligibility, floors, bounds, first-route priority and source-key semantics.

1. Source span rejection moves ahead of AST walking. A rejected span never reached tokenization before either. Helper duplicate detection uses the exact original absolute start/end pair and the already selected first 12 regions, before tokenization rather than afterward.
2. For a statement with n behaviour nodes, min(n, 401) preserves whether the region's total is in [20, 400]. If any statement exceeds 400 the region is necessarily rejected; otherwise all cached counts are exact. No eligible body is truncated.
3. node_tokens visits the empty wrapper arguments (which emit no tokens), then each top-level statement independently. Concatenating the cached token list of each statement in body order therefore preserves the original sequence exactly, including each statement's breadth-first traversal. Nested subtrees are not independently concatenated. Counter insertion and floating-point summation order consequently stay unchanged.
4. Statement caches live only inside _representations and do not escape with their ASTs. Each block receives its own token list; immutable strings may be shared. Fallback blocks retain their existing independent retained-anchor sets.
5. The standalone query cache uses the exact existing _source_key fields. Known indexed objects retain their existing identity plus source-key fast path. New objects, changed source, language, declaration presence and coordinates are handled through the same representation rules. The cache holds one source key and at most 12 original / 13 fallback blocks. Reindexing clears it; Function objects and ASTs are not retained. Whole-function query tokens are never memoized, so mutation of tokens still changes the full-function cosine floor.
6. _best reorders pure necessary guards, never the region loops or cosine summation. It still accepts only strictly greater scores, preserving earliest-region tie ownership. Sorting the selected shared-token set only once changes neither the selected region nor evidence order. _pool, allowed-callback invocation order, ranking, deduplication, IDF fit, candidate floors and constants are unchanged.

Empirical proof supplements this argument: parity.py compares every representation and posting on ten exact backgrounds; every recorded query on the three benchmark backgrounds; every known gold query on all ten; deterministic standalone and source-edited samples; native object identity; float.hex values; direct similarity and shared evidence for returned candidates. Hashes cover ordered sequences, not approximate numeric summaries.
