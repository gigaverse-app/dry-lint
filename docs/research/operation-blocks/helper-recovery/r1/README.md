# Complete helpers recover bounded operations missed by region boundaries

Adding one complete helper body, only when the original operation-block route abstains, produced three new Sonnet report-bearing **bounded shared-operation opportunities** among 37 newly funded public pairs. Independent blinded source review accepted all three scopes: unverified TLS context construction, per-chunk streaming hook/ModelResponse accumulation, and custom-key hook invocation. Existing winners remain first. This package records the first round; the actual balanced Haiku shadow is a separate comparison.

The complete public sweep found 164 extra directional winners, 48 admitted by the unchanged estimated $.04 concept-policy campaign, and 40 distinct pairs. Endpoint/family sampling selected 37 pairs plus 16 independent controls. The original comparator is baseline top 3 + explicit TF-IDF top 20 at .35 + original `operation-blocks:1`. The treatment appends a fallback only when the original plugin has no allowed unseen winner. It keeps original thresholds and caps and adds at most one complete helper body: maximum 13 regions, 8 anchors, 64 region postings and 64 parents. Full candidate functions, including signatures and documentation, remain unchanged.

Two Jev reports overlap the three Sonnet reports; its remaining SSE normalization finding is independently bounded-useful. All four unique report-bearing opportunities have a complete-function reporting observation, but **seven of the 106 questions have a truncated Jev body**, including the two overlapping Jev positives. The actual renderer limits Jev bodies to 8,000 characters. All 53 Candidates, all 53 Claude questions, and all source reviews contain complete native functions. The replay exposes 99 full questions and 7 truncated questions and separates full/truncated report counts. It does not claim the historical paired run meets the full-function requirement on every question.

The scoped recommendations matter. TLS extraction must preserve `ws://` early-return behavior, the other caller's `wss://` guard, shared-getter/error timing and fresh context allocation. Streaming extraction must preserve None versus empty-string hook inputs, non-ModelResponse branches, fast paths and cleanup. Custom-key extraction must preserve request identity/type, label-specific errors, hook timing and differing result/message reads. These are not drop-in whole-function substitutions. Exact accepted constraints are in `source-decisions.jsonl.gz`; original provider advice is retained unedited in `answers.jsonl.gz`.

The first round cost **$0.44025052** in 106 fresh provider requests, separate from the simulated $.04 per-change ledger. Three candidate pairs belong to development components; 34 overlap prior family proxies. None is a fresh confirmation family. These new useful pair instances support an opt-in development gain, not independent-family generalization or default enablement. No source/provider outcome selected the first-round queue.

## Run without providers or dependencies

```bash
python replay.py
python test_replay_policy.py
python verify_hashes.py
```

Python 3.11+ and the standard library are sufficient. The replay recomputes normal concept charges from full functions and the exact template, replays 735 ordered admission rows in 103 nonempty arms, checks exact request identities, validates rendered input against native bodies **including the explicit historical Jev truncation**, and joins canonical report decisions to independent scoped source decisions. A report requires a non-`separate` label and score at least .80; model assessments are excluded. This diagnostic has no escalation or deferred findings. Three original arms have zero considered candidates; they are measured empty, not missing evidence. `replay-result.json` records the expected output. `SHA256SUMS.json` lists every supplied file except itself.

This is result replay from recorded answers, not a checksum-only auditor and not a claim that a model answer is locally deterministic. No credential lookup, network request, provider SDK or target-code execution occurs. `verify_hashes.py` is a separate integrity check.

## What is supplied

- `cases.jsonl.gz`: full Candidate objects, immutable source/body/blob/span proofs and public source links.
- `admissions.jsonl.gz`: complete original/treatment ordered $.04 ledgers, including rejected pairs and complete candidate source.
- `questions.jsonl.gz` and `answers.jsonl.gz`: exact rendered questions, identity/model/prompt/options, raw responses, normalized verdicts, usage and fresh cost.
- `source-decisions.jsonl.gz`: all 53 independently source-reviewed positive, negative, already-shared and related records, with exact bodies and constraints. The canonical historical gold files were not changed.
- `retrieval-recordings.jsonl.gz`: exact same-query ranks/scores, first-loss stages, original/treatment admissions and the frozen split.
- `baseline_operation_blocks.py`, `helper_fallback_v1.py`, `recipe.json`, and `configuration.json`: actual frozen implementation and experiment configuration against dry-lint commit `73709fd`.
- `concept-prompt.txt` and `shared-operations-prompt.txt`: exact text policies. Historical file-prefix context appears in Jev; these Claude templates omit it.
- MIT license texts for the selected LiteLLM and OpenHands source, and the exact Apache 2.0 license for dry-lint. No selected source or admission endpoint is under LiteLLM's restricted enterprise directory.

No whole background or private/Kaizen source is bundled. Full retrieval refitting still needs dry-lint commit `73709fd` and the complete pinned background/native-source inputs identified by the case proofs; the sparse IDF fit must never be reconstructed from this selected subset. `retrieval-recordings.jsonl.gz` is recorded retrieval evidence, not a substitute for the complete corpus. The separate candidate production patch and full supported-gold/runtime receipts accompany the parent addendum.

Do not interpret Sonnet scores as Haiku scores, candidate exposures as reports, unknowns as negatives, or these single-query cold admissions as observed PR traffic. The balanced native comparison must include displaced prior exploration admissions and their exact answers.
